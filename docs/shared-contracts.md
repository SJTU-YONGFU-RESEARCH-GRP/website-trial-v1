# Shared full-stack contract v1

Status: **frozen for implementation**. Breaking changes require a new schema version and migration.

The executable TypeScript definitions live in `shared/contracts/v1.ts`. Benchmark, Digital, and PPA modules may depend on this contract and shared backend services, but must not import one another's implementation.

## Identity and authorization

- Roles are `admin` and `user`.
- Anonymous callers may read published results only.
- Authentication is a server-side session referenced by an HttpOnly cookie. Session IDs rotate at login. Mutating API requests require the session plus a matching CSRF token.
- A user may read only their own jobs, events, logs, artifacts, and private results. Admin access is explicit and audited.
- Users are created by administrators or the `admin:create` CLI. No public registration and no default password exist.
- Passwords use Node's Argon2id implementation with a per-password random salt. Password hashes and session secrets never enter logs or API responses.

## Job and result state

Job states are exactly:

`draft → validating → ready → queued → running → succeeded|failed|cancelled|interrupted`

Retry creates a new job linked by `retryOfJobId`; it does not rewrite history. On worker startup, stale `running` jobs become `interrupted`. Cancellation targets the spawned process group with SIGTERM, waits the configured grace period, then uses SIGKILL if necessary.

Result lifecycle is independent: `private`, `published`, `unpublished`, or `deleted`. A result row and its final artifact namespace are created in one database transaction only after all required steps and parser validation succeed. Failed/partial output stays under the job workspace and never appears in result list APIs.

## Persistent records

Versioned SQLite migrations own these tables:

- `users`, `sessions`;
- `tool_configurations`, `tool_health_checks`, `technology_libraries`;
- `jobs`, `job_steps`, `job_events`, `artifacts`;
- `benchmark_results`, `digital_results`, `ppa_results`;
- `audit_logs`.

JSON columns store only versioned snapshots defined in `shared/contracts/v1.ts`. Every job freezes its input manifest, SHA-256 hashes, normalized parameters, capability version, tool-configuration snapshot and tool-version probe. Later administrator edits cannot change an already queued job.

## Storage and atomic publication

`EDA_STORAGE_ROOT` is required outside the source repository in production. A job owns exactly:

```text
<storageRoot>/jobs/<jobId>/
  input/
  work/
  output/
  logs/
  artifacts/
  manifest.json
```

The backend resolves every path with `realpath`/parent containment checks. Tool working directories are always under the owning job. Inputs are immutable after the draft becomes ready. Modules publish into a temporary directory under `<storageRoot>/publishing/`, validate it, then atomically rename it to `<storageRoot>/results/<module>/<resultId>/` before committing the result transaction.

Tools never write into their repository, the website repository, or another job. Uploaded shell, Python, Makefile, and Tcl files are never executed. PPA configurations and tool scripts are generated by adapters from allowlisted values.

## Queue isolation

There are three persistent queue groups: `benchmark`, `digital`, and `ppa`. Each has independent administrator-configured concurrency and claims only its own queued rows. A worker failure is contained to its claimed job; no module imports another module's worker or parser.

Sweep parents contain independent child jobs. A failed point does not delete successful siblings. The validated Cartesian product and configured maximum are recorded before a sweep can start.

## Module boundary

Each module exports one `ModuleAdapterV1`:

- `capabilities(context)` returns probed tools and parameter/input schemas;
- `validateDraft(context)` validates file mapping and parameters without execution;
- `buildPlan(context)` returns exact steps and process/config mappings;
- `executeStep(context)` executes one allowlisted step;
- `parseResult(context)` parses native output to the module result schema;
- `publishResult(context)` validates the publish payload;
- `collectArtifacts(context)` declares retained artifacts.

Only shared auth, database, jobs, storage, audit, tool registry, file validation and v1 API contracts may be imported across modules.

## Process contract

- All native processes use `spawn`/`execFile` with an executable selected from an administrator-owned `ToolConfiguration` and a string argv array produced by an adapter.
- `shell` is always false. User input cannot choose the executable, working directory, environment variable name, or arbitrary config key.
- Environment injection is an adapter allowlist intersected with configured variables. Secrets are redacted from persisted logs.
- stdout and stderr stream into separate log artifacts and append ordered `job_events`.
- Runtime, output bytes, file count, process count, per-user concurrency, module concurrency and storage quotas are enforced server-side.

## Upload contract

Draft creation uses multipart streaming. Each file part includes a normalized relative path and role mapping. Accepted paths are relative POSIX paths without empty, dot, parent, NUL or absolute segments. Duplicate normalized paths, symbolic links, special files, signature/extension mismatches and limit violations fail preflight.

The server computes SHA-256 while streaming to a draft input area. It scans textual include directives and reports unresolved dependencies. The unified UI offers single file, multiple files and folder selection while retaining `webkitRelativePath`.

Selecting files does not execute or publish. The sequence is upload → map → parameters → preflight → planned operations → explicit Start → queue.

## API contract

- JSON responses use `eda.api.v1` envelopes and structured errors.
- List APIs use cursor pagination, filters and `updatedAt`/ETag.
- Job events are persisted before SSE delivery. `/events` accepts `Last-Event-ID`; polling `GET /api/jobs/:id` is the recovery path.
- Result list visibility is enforced in SQL/repository methods, not only in the frontend.
- OpenAPI is generated from the same route schemas and served by the production backend.

The minimum endpoint set is the one specified in the goal: auth; module capabilities/drafts; job start/list/detail/events/cancel/retry/artifacts; artifact download; three result APIs; and administrator users/tools/jobs/results/technologies/audit APIs.

## Legacy data

Bundled `data/` remains readable. A migration imports it once with `origin = legacy-bundled` and stable source IDs. Dynamic APIs merge database results with migrated legacy records; new computation never writes source files or generated TypeScript. A GitHub Pages build, if retained, is explicitly read-only and disables auth, upload, and Start.
